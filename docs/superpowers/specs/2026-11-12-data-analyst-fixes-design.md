## 3. Handoff redesign

### 3.1 `scripts/data/handoff.py` (new; data-analyst may run it)

Command:

```
handoff.py build --session ID --status needs_approval|completed|blocked|failed --notes <session-relative json>
```

Inputs:
- **Notes file**, agent-authored, e.g. `handoff_notes.json` in the session root:
  ```json
  {
    "actions": ["..."],
    "assumptions": ["..."],
    "validation_checks": ["..."],
    "decisions": [{"id": "D1", "question": "...", "artifact": "outputs/x.csv"}],
    "blocked": [{"what": "...", "why": "...", "remediation": "..."}]
  }
  ```
  `artifact` is optional. Unknown keys are rejected.
- **Generated by the script, never by the agent:**
  - `schema_version: 1` (integer), `specialist: "data_analyst"`, `stage: "data"`;
  - `session_id` and `derived_from_session_id` from `identity.json`;
  - `recommended_next_stage: null`.
  - **`artifacts`**: `manifest.json`, `sources.jsonl`, both index files (when present), and every file listed in the manifest. Each entry is `{"path": "runs/data-analyst/<id>/...", "sha256": "..."}`, with repo-relative paths and hashes computed after `manifest.py verify` passes. This fixes H1 and #12.
  - **`decisions_required`**:
    - one entry per manifest proposal: `{"id", "kind", "target_layer", "path", "sha256", "question": "Approve, edit or reject <kind> for <layer>"}`;
    - then each notes decision: `{"id", "question", "artifact"?, "sha256"?}`, where `sha256` is computed when `artifact` is given;
    - then each `blocked` item as `{"id": "B<n>", "question": "<what> — <why>; remediation: <remediation>"}`.
  - **`validation`**: `{"checks": ["manifest.py verify: passed", *notes.validation_checks], "passed": <bool>}`, where `passed` is false when the status is `blocked` or `failed`.
- **Status rules** (the script refuses violations; H3):

  | Situation | Status |
  |---|---|
  | Any proposal, including partial results with blocked parts | `needs_approval`; blocked parts are decision items |
  | Outputs only, no proposals, nothing blocked | `completed` |
  | No outputs and no proposals | `blocked` |
  | Verification failed or a script crashed | `failed`; manifest verify may fail; artifacts list only files that exist |

- **Output:** writes `runs/data-analyst/<id>/handoff.json` and prints `Handoff written: runs/data-analyst/<id>/handoff.json sha256=<hex>` as the last line. Rebuilding overwrites it.
- **Guards** (`report.md` is also Write-protected for the agent, since only the recorder writes it):
  - `handoff.json` joins the Write-protected names in `data_guard.check_write`;
  - `handoff.py` joins the R12 allowlist (now `session.py`, `fetch.py`, `manifest.py`, `handoff.py`);
  - the orchestrator guard treats `handoff.py build` like `manifest.py build` (denied in the main session).

### 3.2 Agent reply

The final message is the human-readable report, using the base spec §6.4 headings. Its
last line is exactly `Handoff: runs/data-analyst/<id>/handoff.json sha256=<hex>`. It
contains no inline JSON envelope. The agent definition and `data-workflow` are updated
to match. Hand-written envelopes are forbidden.

### 3.3 Validator (`scripts/codex/validate_handoff.py`)

- **`data_analyst` checks:**
  - run `_data_session_checks` for every status whenever `artifacts` is non-empty;
  - `blocked` with proposals in the manifest is rejected (H3);
  - every `decisions_required` entry is an object with a non-empty `id` and `question`;
  - proposal entries additionally match the manifest's `path` and `sha256`;
  - every proposal has a decision entry, matched by id, not merely by count.
- **Report:** `report.md` in the session root must exist and be byte-identical to `invocation/<integrity.invocation_id>/final_report.md` (which the index registers with a hash). Its absence is an error for `completed` and `needs_approval`.

### 3.4 Orchestrator receive step: `scripts/data/receive.py`

Command:

```
receive.py --session ID --agent-id AID [--transcript-root DIR]
```

The orchestrator guard allows it. It runs no vendored code and no `.venv-data`. Steps:

1. **Locate the capture.** If `integrity.json` is missing, or the invocation is not registered in `runs/index.json`, locate the subagent transcript:
   - search `<transcript-root>/*/*/subagents/agent-<AID>.jsonl`;
   - the default root is `$CLAUDE_CONFIG_DIR/projects`, or `~/.claude/projects`;
   - pick the candidate whose project slug matches the repo path;
   - exactly one match is required.

   Then call `scripts.capture.record_invocation.record(project, payload)` with a synthetic SubagentStop payload. This closes #9 and H4.
2. **Verify and validate.** Run `manifest.verify`, then `validate_handoff` on `handoff.json`.
3. **Report.** Print a decision table (id, kind, target layer, path, short sha) and exit 0. On any failure, exit non-zero with the reason. It never edits shared state.

`CLAUDE.md` gains:
- after each data-analyst completion notification, run `receive.py`;
- never present or act on proposals before `receive.py` passes;
- briefs list every upstream artifact the analyst may read, with path and sha256 (#11).

## 4. Reports written by the recorder (all specialists)

Recorder (`scripts/capture/record_invocation.py`):
- **Final report source (port of #2):** the final report is the last `SubagentHandback` `input.message`, falling back to the last assistant text.
- **Writing `report.md`:** after publishing the invocation capture for a bound session, write `runs/<specialist>/<session>/report.md` from `final_report.md` if it is absent.
  - If it is present and identical: no-op.
  - If it is present and different (a later invocation of the same session): leave it unchanged. The newer report stays in that invocation's `final_report.md`, and the recorder output notes `report_md: "kept-first"`.
  - Data-analyst: `report.md` is written after the integrity verdict, so it is never part of the snapshot comparison.

Other changes:
- **Specialist agent instructions** (`network-curator`, `boolean-dynamics-modeler`, `multicellular-configurator`, `ode-modeler`, `data-analyst`): replace "write report.md through guarded Write" with "return the full report as your final message; the recorder saves it as report.md".
- **`specialist_report_guard.py`:** unchanged. It stays as defence in depth.
- **`CLAUDE.md`:** the "Guarded report Write" and "Specialists write guarded immutable report.md" sentences are rewritten accordingly.
- **Validators:** existing validators that require a Markdown report keep working, because the file now exists after the recorder runs.
- **Unbound invocations:** they have no session directory, so no `report.md` is written. That behaviour is unchanged.

## 6. Plotting

Vendoring:
- **Skills:** add `scientific-visualization` (MIT; 8 network-free CLI scripts, `.mplstyle` assets, palettes) and `seaborn` (BSD-3; no scripts) from the pinned upstream commit `2d2065f`.
- **Lock and notices:** same process as base spec §3.1. `VENDORED_SKILLS` grows to 12. `VENDOR.lock.json`, `VENDOR.md` and `THIRD_PARTY_NOTICES.md` (BSD-3 text for seaborn) are updated.
- **Isolation:** `check_isolation` covers the new names automatically through `VENDORED_SKILLS`.
- **Environment:** add `seaborn==0.13.2` to `setup/data-requirements.txt` and pin `matplotlib` to the version `scientific-visualization` documents (3.11.2), if it resolves with the existing lock; otherwise keep the resolved version and record it. Regenerate the lock. Plotly and Kaleido are not added.

New `data-workflow` "Figures" section:
- **Location and format:** figures go in `outputs/figures/`, as PNG (300 dpi) plus SVG. Each is listed in `outputs/index.json` with `units: "none"`, an `identifiers` value, and a one-sentence caption in `description`. The final report references every figure by path.
- **Style:** use `vendor/scientific-agent-skills/scientific-visualization/assets/publication.mplstyle` and its colour-blind-safe palettes. Run `palette_audit.py` on custom palettes.
- **Required figure sets** (produce those that apply):

  | Analysis | Figures |
  |---|---|
  | Cohort / mutation | Alteration landscape (genes × samples or frequency bars by cohort); co-occurrence / mutual-exclusivity heatmap with q-values |
  | Expression QC | Library sizes; PCA coloured by condition/batch |
  | Differential expression | Volcano (labelled top genes, thresholds drawn); MA plot; heatmap of top genes (z-scored) |
  | Enrichment | GSEA dot plot (NES, q); running-score plots for sets cited in the report |
  | DepMap / dependencies | Gene-effect distributions by stratum (violin or box plus points); dependency ranking |
  | Proposal summary | One figure per proposal showing the evidence behind each seed or target (e.g. per-gene evidence tiles) |

- **Honesty rules:** state n per group in the figure or caption; never truncate axes without marking it; show uncertainty where it exists.

## 7. Testing

- **Unit tests (stdlib):**
  - `handoff.py`: build per status rule; refusal of `completed`/`blocked` with proposals; repo-relative paths and fresh hashes; generated decisions; notes schema rejection; protected name.
  - Validator: blocked with proposals rejected; decisions matched by id; report.md identity.
  - `receive.py`: recovery from a transcript fixture when integrity is missing; failure on 0 or 2 transcript matches; happy path prints the table.
  - Recorder: SubagentHandback report; `report.md` write / no-op / kept-first; data-analyst `report.md` written after the verdict.
  - `state.py data-product`: happy path, duplicate, hash mismatch, unknown decision.
  - Ledger terms rule. Guard allowlist additions. Vendor lock with 12 skills.
- **Ported tests:** #1 and #2.
- **Smoke test:** builds `handoff.json` with `handoff.py` and produces at least a volcano plot and a GSEA dot plot under `outputs/figures/` with the vendored style. Receiving goes through `receive.py`, with the capture forced missing first to exercise recovery.
- **Interactive (researcher):** re-run merge gates (b) and (e), plus one data-analyst run that ends with `receive.py` passing and `report.md` written by the recorder.
