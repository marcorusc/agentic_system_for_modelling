# Live benchmark — toy breast-cancer cell-cycle model (NeKo/SIGNOR → MaBoSS)

Started: 2026-10-02T00:48:04+09:00 (Claude Code orchestrator, Opus 5.5, effort high)

Objective of the benchmark: run the full agentic pipeline end to end on a small,
well-understood model (cancer-specific cell cycle with oscillating cyclins), and
record problems, errors and bottlenecks as they emerge. This log is infrastructure
documentation, not scientific state; scientific state lives in the root state files.


> **Action plan:** see [`docs/improvement-plan-2026-10-05.md`](../../improvement-plan-2026-10-05.md) — all findings mapped to actions (agentic system / MCP / software).

## Outcome summary (2026-10-02T02:15+09:00)

**Model.** `toy-cell-cycle`: 19-node ER+ breast-cancer cell-cycle Boolean model (SIGNOR via NeKo, pruned, 5
literature-reviewed manual edges). The final rule set R2 (3 `fitted-for-dynamics`, 16 `database-default` rules)
reproduces ordered CycD → CycE → CycA → CycB waves and recurrent cycling. It also arrests in G1 when ESR1 is off or
CDK4/6 are knocked out, including from S and G2/M states. Main limitation: only ~32 % of single-trajectory cycles are
strictly canonical, because the model omits Emi1/Cdh1 G1 licensing.

**Did the pipeline work end to end?** Yes: specification → NeKo (3 sessions) → literature review (30 edges) → two
topology revisions → typed handoff → MaBoSS baseline → rule refinement → independent review ×2 stages → verification.
The pipeline's gates did their job. Specialists never mutated or exported without explicit instruction, and they
stopped with clarification blocks when blocked. The reviewers caught real errors, including the orchestrator's own.

**Cost and time.** ~87 min wall clock. 13 subagent invocations totalling ≈1.36 M subagent tokens:
- network-curator ×3: 186 k
- literature-reviewer ×3: 336 k
- boolean-dynamics-modeler ×3: 384 k
- scientific-reviewer ×2: 244 k
- reproducibility-auditor ×2: 212 k

The user was asked 5 batches of decisions (17 questions), all answered with the recommended option.

**Top issues to fix (by impact).**
1. B-017 (P1) NeKo SIF-import loses complex labels and blocks BNET export. One-line fix at `neko/core/network.py:338`.
2. B-001/B-002/B-030/B-035 (P1/P2) Modelling servers are registered at user scope with project-wide allow rules. This
   breaks orchestrator isolation and probably collides with the inline servers (MaBoSS "Connection closed" /
   "failed to connect").
3. B-005/B-020/B-025 (P2) Artifacts land in site-packages; the Claude path has no documented capture/verify step;
   MaBoSS mutants and plots are not persisted. The orchestrator spent ~20 % of its effort on manual capture and hashing.
4. B-010/B-016 (P2) NeKo has no add-interaction or re-sign tool, so topology edits are hand-edited SIFs.
5. B-024/B-028 (P2) The stage gate is not mechanically enforced. The orchestrator started downstream work before
   ratification; the auditor caught it.
6. B-015/B-031/B-036 (P2) The orchestrator's own error classes: unstructured evidence reports, shell quoting, and
   prose validation criteria. A small structured-evidence footer, a state-update helper and executable criteria
   would remove them.

**Bottlenecks.** Literature review is the largest per-edge cost (~8–28 k tokens per edge; 4 search-only candidate
edges cost 114 k). The MaBoSS refinement and verification invocations cost 124–168 k each. Waiting for user decisions
was short (~1–2 min per batch). Round trips caused by ephemeral sessions (SIF re-import per revision) were cheap
(2–4 min) and worked as designed.
